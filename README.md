# ヤッツィーのスコア帳

物理のサイコロで遊ぶ、2〜6人用のスコア記録アプリです。Cloudflare WorkersとDurable Objectsで動きます。

## 開発

Node.js 22.18以降を使用します（テストでNode.jsのTypeScript実行機能を使用）。

```sh
npm install
npm run dev
```

表示されたローカルURLをブラウザで開いてください。フロントエンドはWrangler起動時にビルドされます。ローカルのゲームデータは`.wrangler/state`に保存されます。

## 遊び方

1. 名前を入力してルームを作成します。
2. 「招待リンクを共有」を開き、QRコードを各自のスマートフォンのカメラで読み取って参加します。招待リンクや8文字のルームコードでも参加できます。
3. 2〜6人がそろったら、ホストがゲームを開始します。開始後の新規参加はできません。
4. サイコロを振り、自分のスコア画面で役をタップして点数を記録します。左右フリックまたはタブで他のプレイヤーの記録を確認できます。
5. 全員が13項目を記録すると、最終得点と順位が表示されます。同点の場合は同順位です。

記録済みの項目は修正・取り消しできます。最終結果の表示後も修正でき、取り消しで未記録の項目ができた場合はゲーム中の表示に戻ります。

最終結果の「Xで結果をシェア」から、自分の合計点・順位・アプリのトップページへのリンクを入れた投稿画面を別タブで開けます。投稿文はX側で編集して送信できます。

## 得点とルール

- 数字の6項目と役の7項目を記録します。未記録と0点は別に扱います。
- ルーム作成時にストレートの条件を選べます。「通常」は小が4個連続、大が5個連続。「出目指定」は小が1・2・3・4・5の5個、大が2・3・4・5・6の5個です。どちらも小は30点、大は40点で、並び順は問いません。出目指定はこのアプリのカスタムルールです。設定はルーム全員で共有し、作成後は変更できません。既存ルームは通常ルールとして扱います。
- スリーカード・フォーカード・チャンスは、サイコロの絵で5個の出目を選ぶと、合計を自動計算します。スリーカード・フォーカードは役の成立も確認し、不成立なら0点になります。チャンスは組み合わせによらず5個すべての合計です。出目と計算結果は保存され、修正時にも確認できます。
- 上段合計が63点以上なら35点を自動加算します。
- ヤッツィー欄に50点を記録済みなら、別の項目の入力時に追加ボーナスを選択できます。1ターンにつき100点を加算し、修正時の重複加算を防ぎます。
- ジョーカールールに沿う点数を手動で選択できます。スリーカード・フォーカード・チャンス以外の役の成立、ジョーカーの記録先、プレイ順はプレイヤー同士で確認する前提です。
- [Hasbro公式ルール](https://instructions.hasbro.com/en-us/instruction/yahtzee)、[追加ヤッツィーとジョーカールール](https://hasbro-new.custhelp.com/app/answers/detail_uk/a_id/211/kw/yahtzee%20not%20working%20on%20ipad)を参照しています。

### ジョーカールール

ヤッツィー欄をすでに使ったあとに5個同じ目が出たとき、ほかの欄に記録するための特別ルールです。ヤッツィー欄が50点でも0点でも使えます。

たとえば、6・6・6・6・6が出た場合は、次の順に記録します。

1. シックス欄が空いていれば、そこに30点を記録します。
2. シックス欄が記録済みなら、空いている役の欄から1つを選びます。得点は下表のとおりです。
3. 役の欄もすべて記録済みなら、残っている数字の欄に0点を記録します。

| 選んだ役の欄       | 6が5個の場合の得点 |
| ------------------ | -----------------: |
| スリーカード       |               30点 |
| フォーカード       |               30点 |
| フルハウス         |               25点 |
| スモールストレート |               30点 |
| ラージストレート   |               40点 |
| チャンス           |               30点 |

スリーカード・フォーカードは、それぞれ「3個以上同じ」「4個以上同じ」の条件を満たすため、チャンスと同じく5個すべての合計です。フルハウスやストレートは、同じ目5個をその役の代わりに使えます。

ヤッツィー欄が50点なら、そのターンは記録先の得点に加えて100点のボーナスが付きます。たとえばシックス欄に30点を記録した場合、そのターンの加点は30＋100＝130点です。アプリでは「このターンもヤッツィー！」を選んで追加します。ヤッツィー欄が0点の場合は、ジョーカーは使えますが100点のボーナスは付きません。

## 同期と本人の識別

1ルームを1つのSQLiteベースのDurable Objectで管理し、保存した状態をWebSocketで全員へ配信します。WebSocketはHibernation APIを使い、切断時はブラウザが再接続して最新状態を受信します。

ルームは作成・参加・開始・スコア変更・名前変更・退出の最終更新から7日後に自動削除します。閲覧・再接続・同期用のpingでは期限を延長しません。ゲームの終了前後にかかわらず、Alarmsから`storage.deleteAll()`でデータと保存領域を削除し、接続中のブラウザには保存期限切れを表示します。期限後は同じコードから記録を開けません。

この機能の導入前に作られたルームは、導入後の初回アクセス時から7日間保存します。既存ルームを一括で巡回する処理はないため、以降アクセスされない古いルームには期限が設定されません。

本人の識別にはHttpOnly Cookieを使用し、サーバーにはトークンのハッシュだけを保存します。他の人の記録は編集できません。同じブラウザ・同じURLで再度開けば復帰できます。Cookieを削除した場合や別のブラウザ・別の端末からは、同じプレイヤーとしての復帰はできません。

招待リンク・ルームコードを知っている人は、ルームの記録を閲覧できます。スコア記録アプリには、アカウント登録やログイン、サイコロを振る機能はありません。

## おまけ：3Dサイコロ

`public/dice.html` は、スコア記録アプリから独立したサイコロ用のページです。HTML内にCSSとJavaScriptをすべて含み、ファイルを直接ブラウザで開くだけで使えます。外部ライブラリや通信、ビルドは不要です。

- 5個のサイコロを3Dアニメーション付きで振ります。
- ページを開いたときとリセット時の出目の表示はランダムです。振った回数には数えません。
- 「3Dアニメーション」で回転のオン・オフを切り替えられます。初期状態は端末の「視差効果を減らす」設定に合わせます。端末で視差効果を減らしていても、このページではオンにできます。
- トレイの上部に「初回」「振り直し1回目」など、現在の回数を表示します。
- 振ったサイコロをタップするとキープでき、残りだけを振り直せます。もう一度タップするとキープを解除します。
- 「リセット」で出目・キープ・振った回数を初期状態に戻します。アニメーション中のリセットもできます。

振る回数に制限はありません。結果の保存やスコア記録アプリへの連携は行いません。デプロイ後は `/dice` からも開けます。

このファイルのインラインCSS・JavaScriptを変更した場合は、HTML内のCSPのSHA-256ハッシュも更新してください。`public/_headers` では、このページだけHTML自身のCSPを使用します。

## 検証

```sh
npm run check            # Worker/ブラウザの型チェックと得点計算のテスト
npm run test:integration # ローカルWorkerを起動し、HTTP/WebSocketを使って検証
```

統合テストは8791番ポートと一時ディレクトリを使用します。既存の開発サーバーを使う場合は`TEST_BASE_URL=http://localhost:8787 npm run test:integration`で実行できます。

## APIのレート制限

Durable Objectへの転送前に、Workers Rate Limiting bindingでIP単位の制限を適用します。存在しないルームへのアクセスや不正なAPIリクエストもAPI全体の枠を消費します。

| バインディング | 対象 | 1 IP・60秒あたりの設定値 |
| --- | --- | ---: |
| API_RATE_LIMITER | 全APIリクエスト | 300 |
| CREATE_RATE_LIMITER | POST /api/rooms | 5 |
| WRITE_RATE_LIMITER | 作成以外の更新・参加など | 120 |
| LIVE_RATE_LIMITER | GET /api/rooms/:code/live（接続開始） | 60 |

API全体の制限と、該当する操作別の制限を両方適用します。同じWi-Fi・携帯回線の出口IPでは枠を共有します。静的ページ、サイコロページ、接続済みWebSocketの通知やpingは対象外です。WebSocketの同時接続数の上限は今回の変更には含みません。

超過時はDOを呼び出さず、JSONの日本語エラー・HTTP 429・Retry-After: 60を返します。通常操作では既存のエラー表示で案内し、WebSocketの接続失敗は既存の待機付き再接続で回復します。制限サービスのエラー時は制限を迂回せず503にします。IPはCloudflareが設定するCF-Connecting-IPを使い、CookieやX-Forwarded-Forは使用しません。ヘッダーがないローカルリクエストも共通のunknown枠で制限します。

設定はwrangler.jsoncのratelimitsにあります。各simple.limitで回数、simple.periodで期間（10または60秒）を変更できます。namespace_idはこのアプリ用に26102601〜26102604を割り当てています。同じCloudflareアカウントの別Workerですでに使っているIDがあれば、重複しない正の整数文字列へ変更してください。管理画面での名前空間作成やSecretの登録は不要です。変更後はnpm run cf-typegenで型を生成し、npm run deployでコードと設定を反映します。WAFルールの手動設定は、この機能を動かすためには不要です。

これはCloudflareの拠点ごとの概算制限で、設定値を一時的に超えることがあります。IP分散による回避やIPv6アドレスの切り替え、Worker自体への大量アクセス、厳密な課金上限には対応しません。TurnstileやWAFは別途追加する対策です。詳しくは[Rate Limiting公式仕様](https://developers.cloudflare.com/workers/runtime-apis/bindings/rate-limit/)を参照してください。

## デプロイ

```sh
npm run deploy
```

既存のDurable Objectクラス名`MyDurableObject`と`v1`マイグレーションを維持しています。バインディング変更後は`npm run cf-typegen`で型定義を再生成してください。

実装時にはCloudflareの[Durable Objectsの設計指針](https://developers.cloudflare.com/durable-objects/best-practices/rules-of-durable-objects/)、[WebSocket Hibernation](https://developers.cloudflare.com/durable-objects/best-practices/websockets/)、[SQLiteストレージ](https://developers.cloudflare.com/durable-objects/api/sqlite-storage-api/)を参照しています。
