# ヤッツィーのスコア帳

物理のサイコロで遊ぶ、2〜6人用のスコア記録アプリです。Cloudflare WorkersとDurable Objectsで動きます。

## 開発

Node.js 22.18以降を使用します（テストでNode.jsのTypeScript実行機能を使用）。

```sh
npm install
npm run dev
```

表示されたローカルURLをブラウザで開いてください。フロントエンドはWrangler起動時にビルドされます。ローカルのゲームデータは`.wrangler/state`に保存されます。

## 遊び方

1. 名前を入力してルームを作成します。
2. 招待リンクまたは8文字のルームコードを共有し、各自のブラウザから参加します。
3. 2〜6人がそろったら、ホストがゲームを開始します。開始後の新規参加はできません。
4. サイコロを振り、自分のスコア画面で役をタップして点数を記録します。左右フリックまたはタブで他のプレイヤーの記録を確認できます。
5. 全員が13項目を記録すると、最終得点と順位が表示されます。同点の場合は同順位です。

記録済みの項目は修正・取り消しできます。最終結果の表示後も修正でき、取り消しで未記録の項目ができた場合はゲーム中の表示に戻ります。

## 得点とルール

- 数字の6項目と役の7項目を記録します。未記録と0点は別に扱います。
- スリーカード・フォーカードは、5個の出目を入力すると役の成立を確認し、5個すべての合計を自動計算します。出目と計算結果は保存され、修正時にも確認できます。役が成立しない場合は0点です。
- 上段合計が63点以上なら35点を自動加算します。
- ヤッツィー欄に50点を記録済みなら、別の項目の入力時に追加ボーナスを選択できます。1ターンにつき100点を加算し、修正時の重複加算を防ぎます。
- ジョーカールールに沿う点数を手動で選択できます。スリーカード・フォーカード以外の役の成立、ジョーカーの記録先、プレイ順はプレイヤー同士で確認する前提です。
- [Hasbro公式ルール](https://instructions.hasbro.com/en-us/instruction/yahtzee)、[追加ヤッツィーとジョーカールール](https://hasbro-new.custhelp.com/app/answers/detail_uk/a_id/211/kw/yahtzee%20not%20working%20on%20ipad)を参照しています。

### ジョーカールール

ヤッツィー欄をすでに使ったあとに5個同じ目が出たとき、ほかの欄に記録するための特別ルールです。ヤッツィー欄が50点でも0点でも使えます。

たとえば、6・6・6・6・6が出た場合は、次の順に記録します。

1. シックス欄が空いていれば、そこに30点を記録します。
2. シックス欄が記録済みなら、空いている役の欄から1つを選びます。得点は下表のとおりです。
3. 役の欄もすべて記録済みなら、残っている数字の欄に0点を記録します。

| 選んだ役の欄       | 6が5個の場合の得点 |
| ------------------ | -----------------: |
| スリーカード       |               30点 |
| フォーカード       |               30点 |
| フルハウス         |               25点 |
| スモールストレート |               30点 |
| ラージストレート   |               40点 |
| チャンス           |               30点 |

スリーカード・フォーカードは、それぞれ「3個以上同じ」「4個以上同じ」の条件を満たすため、チャンスと同じく5個すべての合計です。フルハウスやストレートは、同じ目5個をその役の代わりに使えます。

ヤッツィー欄が50点なら、そのターンは記録先の得点に加えて100点のボーナスが付きます。たとえばシックス欄に30点を記録した場合、そのターンの加点は30＋100＝130点です。アプリでは「このターンもヤッツィー！」を選んで追加します。ヤッツィー欄が0点の場合は、ジョーカーは使えますが100点のボーナスは付きません。

## 同期と本人の識別

1ルームを1つのSQLiteベースのDurable Objectで管理し、保存した状態をWebSocketで全員へ配信します。WebSocketはHibernation APIを使い、切断時はブラウザが再接続して最新状態を受信します。

本人の識別にはHttpOnly Cookieを使用し、サーバーにはトークンのハッシュだけを保存します。他の人の記録は編集できません。同じブラウザ・同じURLで再度開けば復帰できます。Cookieを削除した場合や別のブラウザ・別の端末からは、同じプレイヤーとしての復帰はできません。

招待リンク・ルームコードを知っている人は、ルームの記録を閲覧できます。アカウント登録やログイン、サイコロを振る機能はありません。

## 検証

```sh
npm run check            # Worker/ブラウザの型チェックと得点計算のテスト
npm run test:integration # ローカルWorkerを起動し、HTTP/WebSocketを使って検証
```

統合テストは8791番ポートと一時ディレクトリを使用します。既存の開発サーバーを使う場合は`TEST_BASE_URL=http://localhost:8787 npm run test:integration`で実行できます。

## デプロイ

```sh
npm run deploy
```

既存のDurable Objectクラス名`MyDurableObject`と`v1`マイグレーションを維持しています。バインディング変更後は`npm run cf-typegen`で型定義を再生成してください。

実装時にはCloudflareの[Durable Objectsの設計指針](https://developers.cloudflare.com/durable-objects/best-practices/rules-of-durable-objects/)、[WebSocket Hibernation](https://developers.cloudflare.com/durable-objects/best-practices/websockets/)、[SQLiteストレージ](https://developers.cloudflare.com/durable-objects/api/sqlite-storage-api/)を参照しています。
